# ATV Remote — 功能提案（2026-09-23）

依据：`architecture-review.md`（F1–F15 已修 / O1–O9 未决）+ `remediation-plan.md`（P0–P3 待办）
+ README 现有功能清单。本文只提案**新功能**，不复述修复项；每条注明治的是哪个痛点 / 哪条未决项。
现状核对：`vibrate` / Web Speech / 短语 / mDNS / WoL / 菜单栏在 `static/app.js`、`server.py`、
`atv_backend.py`、`mac/main.swift` 中均不存在（grep 为空），以下提案不与现有功能重复。

## A. 天天用的遥控体验（低成本、高感知）

| # | 功能 | 治什么 | 做法 | 成本 | 验收口径 |
|---|---|---|---|---|---|
| A1 | **智能唤醒** | O3：电视休眠时 `input` 挂 12s，按键排队；现提示用户「先点☀」是绕 | `/api/cmd` 分发前查一次 `dumpsys power`（约 200ms）：屏幕熄灭则**代发唤醒键**再执行原命令；真关机则 1.5s 内返回「电视已关机」 | 低（server 单点，~40 行） | 休眠电视按键延迟 12s → <2s；开机状态行为不变 |
| A2 | **隐私输入模式** | O8：电视上输密码，原文留在手机 `#log` | 输入框旁「👁 隐私」开关：开启后 `#log` 显示 `••••••`、不进历史；默认关（日志有用是取舍） | 极低（纯前端） | 隐私开关下 `#log` 与 localStorage 均无原文 |
| A3 | **🎤 语音输入到搜索框** | 电视搜索用 D-pad 逐字母选是最大摩擦；Apple TV 本就支持中文 | 键盘卡片加麦克风按钮，Web Speech API（`zh-CN`/`en-US`）识别后走现有 `text` 命令（Android 需 ADBKeyboard 已启用，UI 已有三态徽标可复用） | 低（纯前端） | Chrome/Safari 说一句话 → 电视搜索框出字 |
| A4 | **📋 剪贴板直达 + 常用短语** | 输长密码 / 网址要逐字打；「第一集」「原画」等天天打 | 「粘贴」按钮（`navigator.clipboard.readText`）直接发送；下方一排可编辑短语芯片（存 localStorage） | 低 | 手机复制一串 → 一键上电视 |
| A5 | **按键触觉反馈** | 走局域网按键有 50–200ms 延迟，「按没按上」不确定 | 全局按键 `navigator.vibrate(8)` + 设置开关 | 极低 | Android Chrome 上每次按键有明显震感 |

## B. 连接与配网（第一次用和断线的痛）

| # | 功能 | 治什么 | 做法 | 成本 | 验收口径 |
|---|---|---|---|---|---|
| B1 | **Android TV 局域网扫描** | README 唯一「手动输 IP」的设备；adb 自带 mDNS | `adb mdns services` 解析 `_adb-tls-connect._tcp`，点结果即连；扫不到再回退手动框 | 中 | 同一子网扫描出电视并一键连接 |
| B2 | **自动重连 + 记住常用设备** | 服务重启 / 电视掉线后要重新连 | server 记最近 3 台（存 `state.json`），轮询顺带探测，掉了自动重试一次；`recentChips` 已有可扩展 | 低 | 服务重启后手机端 1 个轮询周期内恢复在线 |
| B3 | **服务自发现** | 新手机第一次要知道 Mac 地址 | server 广播 `_atv-remote._tcp`（mDNS，仅标准库做不到则用 `dnssd`/`zeroconf` 依赖或放弃）；现值机方案是 `/api/qr.svg` 二维码（已带 token），把「扫码即连」在 README 里写明 | 中 | 手机浏览器不输 IP 即可打开遥控页（或明确放弃、只保留二维码） |

## C. 原生平台能力（Mac 是主力客户端）

| # | 功能 | 治什么 | 做法 | 成本 | 验收口径 |
|---|---|---|---|---|---|
| C1 | **Mac 菜单栏遥控器** | 每次调音量/暂停都要「打开窗口→找到按钮」；现在是 WebKit 壳 App | `NSStatusItem` + `NSPopover`：音量 ±/静音、播放暂停、方向键、Esc；复用现有 HTTP API，不重写协议 | 中（纯 Swift） | 不打开主窗口完成全部日常操作 |
| C2 | **官方 Shortcuts** | 「电视静音」这类高频动作想一句话/一按触发 | HTTP API 已齐全，写 3–4 个快捷指令（暂停 / 静音 / 观影宏跑 A6）生成 iCloud 链接放 README 与网页卡片；Apple Watch 自动获得复杂指令 | 极低（零代码，只写文档+链接） | iPhone/Watch 上 Siri「看电视」能启动 App |

## D. 场景化（风险图里这台 Apple TV 在**主卧**）

| # | 功能 | 治什么 | 做法 | 成本 | 验收口径 |
|---|---|---|---|---|---|
| D1 | **一键宏/场景** | 「观影」= 开 Netflix+选 profile+进度，每天重复 4–5 次点击 | `/api/cmd` 已支持 text/app；加 `macro` 类型：steps+delay 的 JSON，server 串行执行、前端可视化编辑 | 中 | 「观影模式」一键依次完成启动+输入+确认 |
| D2 | **睡眠定时** | 主卧电视睡着被遥控声吵醒 / 忘了关 | 30/60/90 分钟倒计时，到点发电源键；倒计时要在界面显眼可见 | 低 | 定时到点电视关，中途可取消 |

## 建议路线

- **第一批（都有低成本的共同点，可一个迭代全上）**：A1 智能唤醒（顺带缓解 O3 的用户感知）、A2 隐私模式、A5 触觉、C2 Shortcuts、D2 睡眠定时。
- **第二批**：A3 语音、A4 剪贴板/短语、B2 自动重连、B1 Android 扫描。
- **第三批（平台绑定较重）**：C1 菜单栏 App、D1 宏、B3 服务自发现。
- 提案与未决项的分工：O2（默认无鉴权）仍是**产品决策**，任何新功能都不改变这个前提；A2 只降低 O8 的泄露面，不替代 CSP。
